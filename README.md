## Prerequisites

- An Azure subscription where you can create resource groups and assign RBAC roles.
- Azure CLI, authenticated with `az login`.
- Docker Desktop or another Docker-compatible daemon for container build/run exercises.
- Python 3.11 or later for the Python deployment scripts and sample apps.
- `kubectl` for the AKS tracks.
- .NET 10 SDK for the initial Blazor container exercise.

The scripts create Azure resources and can incur charges. Delete resource groups when a lab is complete. Some resource names include a short hash derived from the signed-in user to avoid global-name collisions.

## Getting Started

1. Clone the repository and initialize the Microsoft Learn materials:


2. Sign in and select the intended subscription:

   ```powershell

   az account set --subscription "<subscription-name-or-id>"
   ```

3. Begin with [Containers](1.%20Containers/) for local Docker and registry basics, then continue to ACA, AKS, or Cosmos DB.

## Running the Python Demos

Each Python demo folder contains its own deployment script. Before running one, open it and replace the placeholder values at the top:

- `rg` or `$rg`: the target resource group name.
- `location` or `$location`: the Azure region.
- `AKS_VM_SIZE`: optionally choose an available AKS node SKU in your region.

Run the script from its demo directory so its relative paths resolve correctly:

```powershell
# Azure Container Apps example
Set-Location ".\2. ACA\aca-deploy-python"
.\azdeploy.ps1

# AKS or Cosmos DB example
Set-Location ".\3. AKS\aks-deploy-python"
python .\azdeploy.py
```

The scripts present interactive menus for provisioning, building and pushing container images, deployment, status checks, and cleanup tasks. Follow the menu order shown in each script. The AKS deployment demo additionally provisions a Microsoft Foundry model deployment; model availability and quota vary by region and subscription.

## Local Application Dependencies

The Python API and client projects keep their dependencies in local `requirements.txt` or `pyproject.toml` files. Create a virtual environment in the specific API or client folder before installing dependencies:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

For a Dockerized API, use the `Dockerfile` located alongside that API source. The deployment scripts use those Dockerfiles when they build images in Azure Container Registry.

## Configuration and Security

Generated `.env` and `.env.ps1` files are ignored by Git. Treat them as local configuration: do not commit service endpoints, tokens, or connection strings. The Cosmos DB demo configures Microsoft Entra ID and Cosmos DB data-plane RBAC for the signed-in user; use the least-privileged roles appropriate for real workloads.
